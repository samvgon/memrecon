# Hand labels

Sam's marks from hand checks, read back from the Probe Hand Check page's database and kept here as the
record. One JSON object per line. Never edited after saving; a later round is a new file.

| File | What it holds |
|---|---|
| `2026-11-07-probe-handcheck-v2-partial.jsonl` | Extractor version 2 (E28) on E27's stratified sample: rows marked so far (about a third of the sessions), and missed details per line. `kind: row` has the row as shown (`detail`, `qualifier`, `field`, `who`, `row_kind`, `status`, `attached_to`), `verdict` (ok or wrong) and `note`; `kind: missed` has the line and `note`. Reviewed together on Nov 7, which led to extractor version 3. |
| `2026-11-07-probe-handcheck-v3.jsonl` | Extractor version 3 (E29) on the same 37 sessions: all 152 rows marked (116 ok, 36 wrong) and 8 lines with missed details. Same fields as version 2, plus `record` (what R is, from the log), `number`, `resolved` and `replaces`. |
| `2026-11-08-probe-handcheck-v4.jsonl` | Extractor version 4 (E30) plus the split pass (E31) on the same 37 sessions: all 183 rows marked (179 ok, 4 wrong; 16 of them parts from the split pass, all ok) and 3 lines with missed details. Same fields as version 3, plus `origin` (`extract` or `split`) and `carried_from` (`v3` when the mark was copied from version 3 because the row was identical in every column the model writes, and Sam left it as it was). |
| `2026-11-08-judge-sample.jsonl` | The frozen judge sample (D21, D60; `scripts/make_judge_sample.py`, seed 21): 70 items, each one of Memora's yes/no sub-questions about one agent answer from E38's control run, stratified by arm, sub-question type and overlap, 20 `tune` and 50 `check`. Columns in `docs/data-dictionary.md`. |
| `2026-11-08-judge-labels.jsonl` | Sam's labels for the 70 items, from the Judge Hand Labels page, as she gave them: `item`, `label` (yes, no or unsure for "Can't tell"; 32, 19, 19), `note`, `sub_id`, `persona`, `arm`, `labelled_at`, `by`. She saw the answer and the sub-question, not Memora's expected answer, the set, or any judge output. |
| `2026-11-08-judge-labels-resolved.jsonl` | The labels used for the judge check: every "Can't tell" resolved by Sam on Nov 8, after labelling and before any judge output: 14 by her rule that something named only as removed or no longer liked is not mentioned, 2 by her rule that a verdict sub-question with figures in brackets is decided by the final verdict, 3 by her answer about the item (J37 yes, J52 yes, J69 no); and J32 changed from yes to no under the first rule. Columns: `item`, `set`, `label` (yes or no), `source` (her own label, which rule, or her answer), `original`, `note`, `sub_id`. 36 yes, 34 no. |
| `2026-11-08-grader-sample.jsonl` | Code-grader sample, version 1 (`scripts/make_grader_sample.py` as first written): 55 items. **Not used**: it put numbers and dates in one group and old values in none, so it drew only 2 numbers and 1 old value; replaced by version 2 before any labelling. |
| `2026-11-08-grader-sample-v2.jsonl` | Code-grader sample, version 2 (D21; seed 40): probes at the end of the history in E38's end-of-history stores, stratified by arm, the code's verdict and kind (numbers, dates, short names and items, long items; half near misses), plus 6 old values per arm. Columns in `docs/data-dictionary.md`. |
