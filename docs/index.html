Keep, Discard, or Verify: write policies for recall-time memory rewrites

When an LLM agent recalls a memory, it can rewrite it to be more useful for the conversation. Should it store that rewrite? This walkthrough shows the system, how we validated the measurements, and what we have found so far. Pick a section, or press → to start.

The question

Should an agent save the memories it rewrites?

When an agent recalls a memory, it can rewrite it to fit the conversation. If it stores that rewrite, the memory can drift from what the user actually said. A real case from our development data:

Stored memory · Jun 2
"The user spent $5.29 on coffee."
User, later that day
"…I just spent $6.96 on a coffee, so I'm trying to be more mindful of my expenses."
↓ the agent rewrites the recalled memory ↓
Old rewrite prompt (v4)
"The user spent $6.96 on a coffee and is trying to be more mindful of their expenses."

✗ drift  a different purchase replaced the remembered one

Frozen prompt (v5b)
"The user spent $5.29 on coffee in an earlier conversation on 2025-06-02."

✓ kept  original detail kept, date added

The system

Only the write policy changes

On every user turn the agent retrieves, selects and rewrites memories; the write policy decides what happens to the rewrite. Everything else is identical.

Rewrite prompt: Times recalled:

Probe = the detail the user stated (here $5.29). Recall 1 shows the real rewrite from our data. Later rewrites are placeholders: whether they drift depends on what the user says next, and that is what Stage 1 measures. Depth builds up the same way regardless. Write policies run on the note arm only; the log arm keeps the user’s own words, is never rewritten, and serves as the reference.
